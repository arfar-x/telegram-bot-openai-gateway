# telegram-bot-openai-gateway

A Telegram bot that is a client of any OpenAI-compatible Chat Completions endpoint. Point it at a hosted
API, a self-hosted server or a gateway, and people use that model or agent from Telegram: direct
messages, groups, forum topics, replies, forwarded messages, photos and files, inline-button questions and
approvals. Specified in [`docs/spec.md`](docs/spec.md) and [`specs/`](specs/glossary.md).

## What it does

- **DMs, groups and forum topics.** In a group it answers when mentioned, replied to, or given a command. Each
  user has their own session per chat and topic.
- **Replies and forwards.** The model is told what was replied to (the user's own quote first) and where a
  forwarded message came from.
- **Media.** Photos, image files and albums go to the model as images; small text files are inlined; other
  files, stickers and locations become a text note. Voice notes are not supported yet.
- **Telegram-friendly answers.** Every request carries a short system note: the user is in Telegram, answers
  should be brief and use Telegram-friendly Markdown and a few emojis, in the user's language. Answers are
  converted to MarkdownV2, split at Telegram's length limit, and resent as plain text if Telegram refuses the
  formatting.
- **Typing and sparing reactions.** Typing is shown while it works. A 👀 appears only on a message waiting
  behind a running turn, or when an answer takes more than 10 seconds, and is removed afterwards.
- **Questions and approvals.** The bot declares one tool, `clarify`. A question, or an approval the endpoint
  wants before it writes, appears as a message with buttons; only the owner can tap.
- **Settings.** `/model`, `/reasoning`, `/set`, `/unset`, `/settings` change what each request sends.
- **Busy sessions.** Messages sent during a turn are queued and merged into the next one; `/stop` cancels.

## Quick start

You need Docker, `make`, a bot token from [@BotFather](https://t.me/BotFather), and an endpoint.

```bash
git clone https://github.com/arfar-x/telegram-bot-openai-gateway.git
cd telegram-bot-openai-gateway
make setup     # creates .env and generates the database password and the encryption key
```

Edit `.env`: set `BOT_TOKEN`, `OPENAI_BASE_URL` (default `https://api.openai.com/v1`) and `DEFAULT_MODEL`. Then:

```bash
make up        # builds and starts the bot and its PostgreSQL
make logs      # wait for: ready as @yourbot
```

## Who may use it

Nobody, until they are linked: there is no allowlist. A person sends `/start <username>` in a private chat and
receives a code. You approve it, supplying the API key that person will act under:

```bash
make codes             # open codes, with the username and Telegram name each person gave
make pair CODE=ABCD2345   # asks for the API key; the person is told they are linked
make links             # linked users
make unlink TG_ID=123  # or USER_NAME=alice@example.org
```

The username in a request is free text, so check that it is who it says before you approve: your approval is
what stops someone claiming another person's account. Each linked user acts under their own key, so an
endpoint that identifies callers by key (for example one that keeps per-user credentials) keeps them apart.
With an endpoint that has no per-user identity, give everyone the same key.

## The endpoint

The bot calls `POST <OPENAI_BASE_URL>/chat/completions` with `stream: true`, a leading `system` message and a
`tools` list holding one function, and `GET <OPENAI_BASE_URL>/models` for `/model`. The endpoint needs to
stream Server-Sent Events in the Chat Completions shape, accept a `system` message, and accept `tools`. It is
tested against mock servers and has been used with an OpenAI-compatible gateway; other servers are untested. The full
contract is in [`specs/002-conversations/contracts/endpoint.md`](specs/002-conversations/contracts/endpoint.md).

## Configuration

Every setting is an environment variable in `.env`; [`.env.example`](.env.example) describes each.

| Variable | Default | Meaning |
|---|---|---|
| `BOT_TOKEN` | required | From @BotFather |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | The endpoint |
| `DEFAULT_MODEL` | required | The model a new session starts with |
| `OPENAI_API_KEY` | empty | Only to list models before a user is linked |
| `DATABASE_URL`, `POSTGRES_PASSWORD` | generated by `make setup` | The bot's PostgreSQL |
| `CREDS_KEY` | generated by `make setup` | Encrypts stored API keys; losing it means linking everyone again |
| `REACTIONS`, `REACTION_DELAY` | `true`, `10` | The sparing 👀 reaction |
| `SHOW_PROGRESS` | `false` | Show the endpoint's reasoning as one self-editing message |
| `REQUEST_TIMEOUT` | `600` | Seconds a request to the endpoint may take in all |
| `HISTORY_MAX_CHARS` | `200000` | History sent with each request; the oldest whole turns are dropped past it |
| `MESSAGE_TEXT_DAYS` | `30` | Days message texts are kept for quoting replies |
| `MAX_CONCURRENT_TURNS` | `2` | Turns one person may have running at once across chats |
| `TELEGRAM_PROXY`, `TELEGRAM_CONNECT_TIMEOUT`, `TELEGRAM_READ_TIMEOUT` | empty, `20`, `30` | Reaching Telegram from a slow or filtered network |
| `WEBHOOK_URL`, `WEBHOOK_SECRET` | empty | Webhook instead of long polling (the secret is required with the URL); see `compose.webhook.yaml` |

Operating it day to day, backups and troubleshooting: [`docs/OPERATOR_GUIDE.md`](docs/OPERATOR_GUIDE.md).

## Develop

```bash
make dev                 # creates .venv with the development dependencies
make test                # unit tests, no services needed
make test-services       # the PostgreSQL tests, against a throwaway container
```

Layout: `domain/` (pure rules) → `application/` (use cases over ports) → `adapters/` (Telegram, the endpoint,
PostgreSQL). `tests/test_boundaries.py` fails if `domain/` or `application/` do I/O, and
`tests/test_spec_coverage.py` fails when a requirement marked `done` has no test claiming it. The rules for
changing the project are in [`.specify/memory/constitution.md`](.specify/memory/constitution.md) and
[`AGENTS.md`](AGENTS.md).
